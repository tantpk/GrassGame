## 1.3 四大核心類別（Classes）與底層數學模型解析

### 1. `WuxiaAudioEngine`（第 247～338 行）：零外部依賴國風音訊合成器

基於瀏覽器原生 `AudioContext` 與振盪器（`OscillatorNode`）實時合成古典仙俠音效，無需載入任何外部音訊檔案：

* **`playTone(freq, type, duration, gainVal)`**：基礎泛音包絡線產生器，採用指數級衰減（`exponentialRampToValueAtTime`）模擬古琴弦音與鐘磬餘韻。

* **`playSwordClash()`**：以 `sawtooth` 鋸齒波從 `2200Hz` 急速滑落至 `600Hz`，模擬太乙飛劍破空交擊之金鐵錚鳴。

* **`playLevelUp()`**：依序彈奏 `C4 (261.63Hz) ➔ E4 (329.63Hz) ➔ G4 (392.00Hz) ➔ C5 (523.25Hz)` 和弦琶音，用於破境飛升與升階。

* **`playQiCharge()`**：以 `440Hz` 三角波疊加 `587.33Hz` 正弦泛音，模擬吐納時天地靈氣入體之溫潤共鳴。

* **`playEpiphanyBell()`**：以 `523.25Hz`、`783.99Hz`、`1046.5Hz` 三重泛音模擬古剎仙鐘，用於觸發「靈台頓悟」、「時辰流轉」與「朱砂落印」。

* **`toggleBGM()`**：以中國傳統五聲音階羽調式（`220Hz, 247Hz, 277Hz, 330Hz, 370Hz, 440Hz`）隨機撥奏古琴松風背景音樂。

### 2. `Character`（第 340～581 行 & 第 4530～4655 行）：角色模型與十重屬性結算管線

管理玩家所有持久化狀態，並透過 `getEffectiveStat(stat)` 按十重疊加管線即時計算六維戰鬥屬性：

* **第一重：境界倍率公式**

  `realmMultiplier = 1 + (realmIndex * 9 + realmLayer) * 0.16`

* **第二重：五維先天道基轉化基礎屬性**

  * **血魄氣血 (`hp`)**：`(380 + rootBone * 32) * realmMultiplier`

  * **洞天真元 (`mp`)**：`(160 + comprehension * 22) * realmMultiplier`

  * **神通殺力 (`atk`)**：`(55 + strength * 6) * realmMultiplier`

  * **道紋靈罡 (`def`)**：`(28 + rootBone * 3.5) * realmMultiplier`

  * **虛空遁速 (`speed`)**：`48 + agility * 3`

  * **會心破綻 (`crit`)**：`7 + Math.floor(agility * 0.25) + Math.floor(luck * 0.15)`

  * **破虛閃避 (`dodge`)**：`5 + Math.floor(agility * 0.25)`

* **第三重：本命裝備基礎屬性 × 祭煉階數倍率**

  遍歷 `equipSlots`（殺伐道兵、護體仙甲、本命奇寶），裝備基礎數值乘上祭煉倍率 `1 + equipEnhance[slot] * 0.12`（最高 +15 階即 `2.8 倍`）。

* **第四重：程序化隨機詞條加成 (`itemAffixes`)**

  累加穿戴裝備上隨機生成的 1～3 條專屬詞條數值（如暴擊 `+12%`、殺力 `+145`、無視防禦 `+210`）。

* **第五重：雙生丹爐火雷融爆加成 (`furnaceFusedLevel`)**

  每升一階（上限 Lv.10）提供神通殺力 `+85`、會心暴擊 `+4%`。

* **第六重：荒古霸王軀階位與三選一淬體引物加成 (`bodyStagesUnlocked` & `bodyRefiningBonus`)**

  每解鎖一階提供氣血 `+950`、靈罡 `+65`，並疊加雷淬（氣血 `+900`／遁速 `+8`）、火淬（氣血 `+850`／殺力 `+45`）、寒髓淬（氣血 `+1000`／靈罡 `+65`）之永久屬性。

* **第七重：太初五極靈竅「剛／柔雙分支」加成 (`acupointBranches`)**

  已貫通之靈竅若選「剛線」每竅提供殺力 `+95`、暴擊 `+4%`；若選「柔線」每竅提供氣血 `+850`、靈罡 `+60`。

* **第八重：本命器靈好感度加成 (`spiritAffection`)**

  器靈好感度每累積 `10 點`（上限 50 點），為氣血、殺力、靈罡提供額外百分比增幅。

* **第九重：吐納悟道「體道感悟」加成 (`wudaoStacks.body`)**

  每層體道感悟（上限 5 層）提升氣血與靈罡 `+3%`（最高 `+15%`）。

* **第十重：終局「守境挑戰」、「逆天改命」與「心魔殿」全域百分比加成**

  守境首勝全屬性 `+1.5%`（每 5 勝再 `+0.5%`）、逆天改命覺醒「改命」特質全屬性 `+3%`、心魔殿每突破 10 層全屬性 `+1%`。

## 14.1 畫布舊幀圖案殘留（Ghosting / Trail Stacking）根因剖析與徹底修復

在先前版本運行時，畫面曾出現飛劍旋轉軌跡、全屏黃色閃光以及傷害飄字永久殘留於 Canvas 上的異常。經深入代碼鏈路除錯，查明兩大根本原因：

1. **多重原型方法覆寫衝突**：代碼庫中歷史版本保留了舊版 `renderV12WildernessView` 與 `startV14WuxiaMowing`，執行時後方舊代碼覆寫了新邏輯，並以舊參數調用了重構後的背景繪製引擎。

2. **引數型別錯位導致清屏迴圈中斷**：舊呼叫傳入 `(ctx, canvas, ...)`，新引擎接收之第一參數為 `worldW`。由於 `0 < [object HTMLCanvasElement]` 判定為假，導致地圖瓦片鋪設迴圈完全跳過，且原先缺乏顯式 `ctx.clearRect`，上一幀像素被永久保留並逐幀疊加。

**修復方案**：

* 徹底清除所有歷史殘留的重複函數定義，保證 `renderV14WuxiaWildernessView` 與 `startV14WuxiaMowing` 為全代碼庫唯一生效入口。

* 在每幀渲染循環 (`loop()`) 開端強制執行雙重清屏：

  ```
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  ctx.fillStyle = "#120f0d";
  ctx.fillRect(0, 0, canvas.width, canvas.height);
  
  ```

* 在 `PixelSpriteEngine.drawPixelArena` 頂部實裝引數型別安全護盾，即使傳入舊版 `canvas` 對象亦能自動正規化為 1200×900 規格，確保 100% 穩定平鋪與清屏。

## 14.2 介面文字遮擋與邊界溢出徹底修復

針對畫布下緣文字半截被擋住及按鈕擁擠問題，進行了全面重構與佈局安全規範：

2. **局內升級浮層自適應滾動**：為 `.pixel-perk-overlay` 注入 `overflow-y: auto; z-index: 60;`，無論屏幕高低，3 張造化突破卡片均能完整展示且支援滾動，絕不被底欄截斷。

## 21.4 「角色不會死亡」問題根因剖析與徹底修復

* **舊版不死 Bug 三大根因**：
  1. 舊版敵方遠程投射物命中主角時寫為 `state.player.hp = Math.max(15, state.player.hp - 5)`，強制將最低氣血鎖死在 `15`，永遠不會歸零。
  2. 舊版 Boss 九幽魔隕命中時寫為 `state.player.hp = Math.max(10, state.player.hp - 12)`，強制將最低氣血鎖死在 `10`。
  3. 舊版小怪與巨型 Boss 近身貼臉碰撞時，缺少對主角本體之距離碰撞檢定與扣血邏輯。
* **v21.0 徹底修復方案 (`damagePlayer(rawDmg, attackerName)`)**：
  1. **移除所有鎖血下限**：徹底刪除 `Math.max(15, ...)` 與 `Math.max(10, ...)`，所有受擊傷害先抵扣「🛡️ 護體玄罡 (`frostShield`)」，護罡擊穿後直接扣減主角氣血直至 `0`。
  2. **實裝全種類敵人近身碰撞與遠程傷害**：
     * 近身碰撞：血刀門徒 `-8 HP`、幽冥妖狼猛撲 `-12 HP`、魔將／魔蠍／鬼將 `-14 HP`、巨型魔尊 Boss `-22 HP`。
     * 遠程與大招：綠毒骨箭 `-9 HP`、赤炎火毒彈 `-11 HP`、九幽死神鐮 `-13 HP`、魔尊血月魔刃 `-16 HP`、九幽魔隕天降 `-24 HP`（依所選難度倍率動態縮放）。
  3. **合理受擊無敵幀 (`invulnerableTimer`) 與紅屏血霧警示**：每次受擊後獲得短暫無敵閃避幀（避免單一瞬間多幀重疊秒殺），同時觸發全畫布邊緣紅框血霧閃爍（`#v21-damage-vignette`）與頭頂雙層血條即時扣減。
  4. **保命法寶與死亡結算觸發**：當 `state.player.hp <= 0` 時，若攜帶未觸發之「🎗️ 九轉不滅金身帶」則觸發一次鎖血逆轉（回復 60% 氣血並震退群魔）；否則立即暫停戰場並彈出 **【💀 道軀隕落 · 戰鬥失敗】** 結算介面！

## 23.1 畫面下方圖案重疊（Bottom Canvas Sprite Overlap / Ghosting）根因剖析與徹底修復

1. **問題根因診斷（對應玩家截圖 `image_e900de.png`）**：
   * 舊版 `syncHighDPICanvasResolution()` 將邏輯視野固定設為 `state.viewW = 480, state.viewH = 420`，並以 `state.renderScale = canvas.width / state.viewW` 進行縮放。
   * 當遊戲容器處於較窄視窗或手機直向比例（例如寬 `415px`、高 `430px`）時，畫布實際對應的邏輯高度達 `497px`，超過了固定的 `state.viewH = 420`。
   * 導致每幀 `ctx.clearRect(0, 0, state.viewW, state.viewH)` 與 `worldCanvas` 地圖貼圖僅覆蓋上半部 `0 ~ 420` 區域，最下方 `420 ~ 497` 的水平帶狀區域既未被清除也無背景覆蓋，任何飛入該區域的靈葫、火蓮、飛劍與粒子便會逐幀無限堆疊殘留！
2. **v23.0 徹底修復方案**：
   * **動態等比例邏輯視野高 (`state.viewH`)**：於 `syncHighDPICanvasResolution()` 動態計算 `state.viewH = Math.max(320, Math.min(680, Math.round(480 * (cssH / cssW))))`，並將物理畫布尺寸嚴格鎖定為 `canvas.width = Math.round(state.viewW * dpr)`、`canvas.height = Math.round(state.viewH * dpr)`、`state.renderScale = dpr`，使邏輯視野與物理畫布 100% 嚴絲合縫。

* **問題根因**：原先 `#app-container` 限制 `max-width: 468px`，且 `.v21-grid-4` 將 4 張靈寵／道體卡片硬塞在同一橫列（每欄僅約 100px 寬），卡片內部又使用左右 `flex` 將像素預覽圖放左邊、長篇進化文字放右邊，導致文字只剩 1 個中文字寬度並被拉長成數十行的直條。

## 26.3 進入遊戲隱藏上方冗長資訊面板 & 長方形主畫面設計
* 進入戰鬥畫面 (`renderV21BattleScreen`) 時，預設將上方所有佔據空間的武器列表、波次面板與靈寵戰陣面板收合隱藏（`#v26-collapsible-top-info { display: none; }`），讓遊戲畫布 (`#v13-canvas-box`) 直接以 **16:10 寬長方形大畫面** 呈現。

## 26.4 手機裝置 Resolution 自動適應與全螢幕視野擴展（解決全螢幕過度放大問題）
* **手機與平板自動適應**：透過 `syncHighDPICanvasResolution()` 監聽 `resize` 與 `orientationchange`，即時讀取裝置的 `getBoundingClientRect()` 與 `window.devicePixelRatio`，在手機上自動將 Canvas 調整為貼合手機螢幕解析度的全屏長方形比例。
* **全螢幕動態擴展邏輯視野（不再將原畫面粗暴放大）**：進入全螢幕後，不再將原本固定的 `480×440` 視野直接拉伸放大到整個螢幕，而是依據放大後的實際螢幕解析度 (`cssW × cssH`) 按比例動態重新計算 `state.viewW = Math.round(cssW / unitZoom)` 與 `state.viewH = Math.round(cssH / unitZoom)`（搭配擴展至 `1600×1100` 的大世界地圖），讓全螢幕展現更寬廣清晰的戰場視野與恰當的角色比例！
